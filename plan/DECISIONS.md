## Standing product directions (owner, 2026-07-19)

- **D-AGENT — everything becomes agentic.** Over time all operations should be executable by the agent; the agent should ultimately have complete control over the platform. Any process the owner performs once should be **teachable / convertible into a reusable agent skill**. Architectural consequences (already aligned with the plan): every operation must exist as a semantic command/API before UI polish (§28.7); agent tools derive from commands (§11.7); P07 workflows are the "teach once, reuse forever" container. New consequence: **P06/P07 must include a "record → skill" path** — capture a performed command sequence and parameterize it into a workflow. Safety framing of §22 (approvals, dry-run, audit, revert) stays in force.
- **D-HERMES — Hermes is the companion agent.** The existing Hermes agent (from the JOY ecosystem) is expected to operate alongside JOY Media for authoring/automation (first concrete duty: HTML scene templates, Q11). Integration boundary to be designed in P06; until then nothing in core may hard-depend on Hermes internals.

**Rule:** changing a DECIDED entry requires a superseding ADR. DEFAULT entries may be used but must be flagged in session reports.
