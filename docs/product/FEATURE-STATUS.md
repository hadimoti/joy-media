# Feature Status

Audited against current source on 2026-10-17 at baseline
`c1fffd59d5078902e031e7684e69c27df40ce607`.

This ledger reports implemented or intentionally limited surfaces. It does not certify that
the installed Windows app, every CLI launcher, or media output is release-ready. See the
[readiness matrix](../qa/READINESS-MATRIX.md) and
[Windows baseline evidence](../qa/evidence/2026-10-17-windows-baseline.md) for scenario status.

| Surface                                                                               | Status       | Current source boundary                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authenticated editor shell and signed-in project workspace                            | production   | Mounted in `apps/editor-web/src/App.tsx` with authenticated browser journeys. Installed Windows acceptance is tracked separately.                                                                                                                                                               |
| Project library lifecycle: create, open, rename, duplicate, trash, restore, and purge | production   | Implemented in `apps/editor-web/src/ProjectLibrary.tsx`, `apps/editor-web/src/project-lifecycle.ts`, and API lifecycle routes/tests. Fresh-process desktop persistence remains open.                                                                                                            |
| Editor workspace and File/Edit/Clip/Agent/View/Window menus                           | production   | `apps/editor-web/src/workspace.ts` defines the workspace panels; `apps/editor-web/src/app-menu.ts` defines the menu actions. Each panel's keyboard, resize, and installed-app workflow is not independently accepted yet.                                                                       |
| Transition and effect preview assets                                                  | production   | `TransitionPreviewCard` and `EffectPreviewMedia` use source-controlled assets under `apps/editor-web/public/`. Preview availability is not proof of final encoded parity.                                                                                                                       |
| JOY Media command-line interface                                                      | experimental | `apps/cli/src/cli.ts` documents agent, project, timeline, worker, render, benchmark, and doctor commands. Windows real-FFmpeg output exists through the source entry; bundle/installed launcher parity, unsupported-feature rejection, and failure recovery remain open.                        |
| Browser export audio and scene capture                                                | experimental | Independent audio lanes and on-demand HTML-scene capture are wired in `apps/editor-web/src/App.tsx`; decoded-file playback, audio/timing parity, and long-run memory acceptance remain open.                                                                                                    |
| Editable-project bundle interchange                                                   | experimental | `apps/editor-web/src/project-package.ts` and the File menu provide versioned editable-project import/export with integrity metadata and embedded originals where available. Fresh-profile media relink and decoded render roundtrip remain open.                                                |
| Built-in JOY Agent Engine (Joy Code + Creative Brief)                                 | experimental | Browser-resident engine and Composer are mounted in `apps/editor-web/src/joy-agent/` and `AgentPanel.tsx`. It uses bounded tool exchange and explicit approval; arbitrary provider billing and full media/frame repair are outside the supported ready claim. Server AI routes return HTTP 410. |
| Workflow recorder, templates, and approval recovery                                   | experimental | Recorder/templates are in `workflow-recorder.ts` and `workflow-templates.ts`; pending approvals can be reviewed and resumed by project/revision. Fixture/deferred media handlers are not final exports.                                                                                         |
| Worker-gated mask video capability                                                    | hidden       | `apps/editor-web/src/MaskInspector.tsx` keeps unavailable Worker capabilities from being advertised as ready.                                                                                                                                                                                   |
| Plugin marketplace                                                                    | hidden       | The mounted plugin host is an SDK/demo boundary. A public catalog, installation/update lifecycle, trust process, and marketplace release are not established.                                                                                                                                   |
| Windows Electron host and local runtime                                               | experimental | `apps/desktop` contains a real Electron main/preload bootstrap, local media/job database, and protected provider-profile boundary. `SqliteProjectStore` is not wired into editor project open/save; derivative jobs can be queued but are not dispatched to completion.                         |
| Windows application packaging                                                         | experimental | `package:staging` assembles an unsigned runnable package for smoke tests. `package-release.mjs` keeps public release packaging owner-gated; staging output is not distributable acceptance. Install/update/rollback/uninstall and a signed candidate remain open.                               |

The baseline command results and classified skips are recorded in the linked evidence note. A
feature stays experimental or hidden until its required user-level scenario passes on the exact
candidate; source presence and unit tests alone do not upgrade it.
