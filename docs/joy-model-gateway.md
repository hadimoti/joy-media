# JOY Model gateway operations

The gateway applies a per-user request limit in memory after request validation, so malformed or disallowed requests do not consume a slot. It resets when the API process restarts, so it is an abuse throttle rather than a durable quota.

The model catalog is a fixed list of five zero-cost OpenRouter `:free` models (`apps/api/src/joy-free-models.ts`), with `nvidia/nemotron-3-super-120b-a12b:free` (text) as the default. The vision models are `google/gemma-4-31b-it:free` and `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`; `thinkingmachines/inkling:free` was dropped in FC3 because OpenRouter only serves it to agentic harnesses (403). `GET /models` returns exactly that list. Any other model id is refused with `MODEL_NOT_ALLOWED`; legacy ids (`openrouter/free`, `minimax/minimax-m3`, `anthropic/claude-3.5-sonnet`, `meta-llama/llama-3.3-70b-instruct`) resolve to the default. Paid models cannot be enabled: `JOY_GATEWAY_PAID_MODEL_ALLOWLIST` is ignored, with a startup warning if it is set.

Fallback: each request has one 85-second deadline shared across all model attempts and response-body reads. Waiting for response headers is limited to 20 seconds per attempt (40 seconds when the request carries images) or the remaining request budget, whichever is shorter. Once a non-stream 200 has its headers, its body is read against the remaining request deadline, since OpenRouter pads slow bodies with leading whitespace keep-alives (leading whitespace is ignored); if no bytes at all arrive for 25 seconds, the attempt falls back. A body read that is cut off by a timeout, abort or stream error is never parsed as a partial body: it is classified as an upstream timeout and falls back while budget remains. A client disconnect aborts the in-flight upstream request and releases the spend reservation. Timeouts and network errors fall through to the next candidate while budget remains. A non-stream HTTP 200 with invalid JSON, an empty body, or a non-completion JSON shape is treated as a model failure (`INVALID_RESPONSE`), logged as `joy-model-gateway: invalid upstream body` with the body length and the first 12 hex characters of its SHA-256 (never the content). Model failures including 404, 429, 5xx, all 403s, provider-level 401s carrying `provider_name` or `failed_routing_step`, and an error in a 200 body or first stream event are retried. An error carried in a 200 body with code 400, 413, or 422 stops immediately as an upstream request error. Key-level 401s and 403s are allowed to fall through the candidate list; `JOY_AGENT_UPSTREAM_AUTH_FAILED` is returned only when every failed attempt is a key-level 401 or key-level 403; a bare 401 after a non-auth failure is reported as busy. When every candidate falls back, the gateway answers `503 JOY_AGENT_MODELS_BUSY` with `retryable: true`, `retryAfterSeconds` (the soonest upstream `Retry-After`, clamped to 5-300 s, else 30) and a matching `Retry-After` header; `vision: true` marks a request whose image models were all busy. Before committing a stream, the gateway reads through the first `data:` event (skipping comment lines such as `: OPENROUTER PROCESSING`), so an initial error or timeout can fall back. An error after stream data has started is logged as `mid_stream_error` and sent as a sanitized terminal `UPSTREAM_STREAM_ERROR` SSE event, and the response ends immediately. `<think>` blocks are stripped from streamed deltas (also on `data:` lines without a space), and text held back as a possible tag prefix is flushed when the choice finishes or the stream ends. Each attempt logs one `joy-model-gateway: upstream attempt` line with model, HTTP status, OpenRouter error code and routing metadata; request bodies and successful response bodies are never logged.

Reasoning: requests to a catalog model flagged `reasoning` (Nano Omni) carry `reasoning: { exclude: true }`. Whatever the model, the gateway also removes `reasoning`, `reasoning_content` and `reasoning_details` from every choice's message and stream delta, and `<think>...</think>` blocks from completion content and streamed deltas, including tags split across delta boundaries, so reasoning never reaches the client's reply or its conversation history. Output is still capped at 8,192 tokens per request.

Messages may carry only `text` and `image_url` parts (https: or data:image/ URLs). A request with images is sent only to the vision models: the requested model if it is one, otherwise Gemma, then Nano Omni. `file`, `input_audio`, `video_url` and unknown part types are refused with `400 UNSUPPORTED_CONTENT_PART`, because OpenRouter can bill file parsing (such as `mistral-ocr` for PDFs) even on a free model. Every forwarded request also pins `plugins` to the free `file-parser` engine (`cloudflare-ai`); client-sent plugins are dropped. Messages are rebuilt from `role`, `content`, `name`, `tool_calls` and `tool_call_id`, and parts from `type`, `text` and `image_url { url, detail }`; any other key is dropped before forwarding. If a response still reports a non-zero `usage.cost`, the API logs `PAID SPEND REPORTED FOR A FREE MODEL` (code `JOY_FREE_MODEL_BILLED`).

Daily spend is reserved against the ledger before requests are forwarded and settled atomically when a response completes. Image inputs reserve a conservative 1,600 prompt tokens per image at the selected model's input price. Reservations older than 15 minutes are ignored and swept at startup and periodically. The cap resets at 00:00 UTC, which is 03:30 in Tehran (Asia/Tehran). A reservation failure returns `503 SPEND_LEDGER_UNAVAILABLE`; a bounded Postgres lock wait returns `503 SPEND_LEDGER_BUSY` before forwarding the request.

After a control-plane deployment, `deploy/deploy-control-plane.sh` runs `tooling/ops/smoke-gateway.mjs`. The smoke targets loopback with a `Host` header, has a 10-second timeout per request, expects public `GET /models` and unauthenticated `POST /chat/completions` to return `200` and `401`, and reports `503 JOY_AGENT_UNCONFIGURED` as a missing OpenRouter systemd credential. Use `--pre-cutover` for the same checks before a manual release switch; configure `JOY_GATEWAY_BASE_URL` and `JOY_GATEWAY_HOST` or pass `--base-url` and `--host`.
