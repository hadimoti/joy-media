## Known gap: RESOLVED (2026-07-20)

The `VisualObjectV1 → RenderNode` bridge that was missing at P10 gate time now exists in `@joy-media/visual-object-renderer`:

- `visualObjectToRenderNode()` maps all five object kinds (`image`/`text`/`shape` → visual nodes; `null`/`camera` → excluded)
- `buildRenderFrameIR()` assembles resolved objects into a validated `RenderFrameIR`
- E2E test proves: full evaluator pipeline → `RenderFrameIR` → `renderPixiPreview` + `renderHeadlessFrame` → pixel-digest parity
- The first exit criterion is upgraded to **Pass**.

**Remaining work for the live preview canvas:** the bridge in `visual-object-renderer` produces rendered frames; the editor-web still needs to wire it to a canvas element. That's the `task_6f29897c` background task's scope.

**Independent re-verification (2026-07-20, separate session):** the pixel-parity claim above was reproduced directly and holds. However, the package's own "typecheck/lint clean" claim did not: `packages/visual-object-renderer/tsconfig.json` was missing project references to `renderer-pixi`, `renderer-headless`, and `golden-render` — a genuinely clean `tsc -b` (all `dist`/`tsconfig.tsbuildinfo` removed first) failed with `Cannot find module '@joy-media/golden-render'`; it had only "passed" earlier because leftover build artifacts from prior work masked the gap. Lint also had 5 real errors (an unused import, three `no-explicit-any` violations, one unused parameter), and the source hadn't been run through prettier. All of it is fixed and re-verified with a second from-scratch clean build; see the `visual-object-renderer` package README/commit history for detail.

## Scope boundary

P10 is bounded by ADR-0015 to exactly two capabilities: a depth-only 2.5D camera (no yaw/pitch, no per-layer 3D tilt) and a restricted expression language. The other eight P10 parking-lot items (multicam, color/HDR, paint/vector tools, audio restoration, interchange formats, render-farm, publishing integrations, enterprise governance) and a true 3D camera remain closed — opening any of them requires its own ADR. The `VisualObjectV1 → RenderNode` rendering bridge was outside P10's originally-scoped work, but closing it turned out to be small and bounded (one new, additive package; nothing in `render-ir` or any renderer changed), so it was completed as a direct follow-on rather than left open. The live pixel-preview canvas (`task_6f29897c`) remains genuinely separate follow-on work — the bridge is a prerequisite for it, not a substitute.
