## 3. Auth — ALREADY SOLVED, do not design OAuth

The owner asked for registration/login "via gmail same as joy-vps web". Verified:

- **joy-vps does NOT use Google OAuth.** It uses an **OTP code emailed to a Gmail address**:
  `bot/webapp_server.py:2178 api_auth_gmail_request`, `:2214 api_auth_gmail_verify`, plus the
  Telegram equivalents at `:2342` / `:2363`. Sending/verification logic in `bot/webapp_api.py`
  (`send_admin_otp`, `verify_admin_otp`, `_joyteam_login_otp_html`).
- **joy-media already implements the same model.** `apps/api/src/media-auth.ts` exports
  `MediaAuthMethod = 'gmail' | 'telegram'`. Routes in `apps/api/src/http-server.ts`:
  `/v1/auth/request-otp` (:567), `/v1/auth/verify-otp` (:578), `/v1/auth/logout` (:589),
  `/v1/auth/session` (:596), `/v1/auth/avatar` (:604). Mailer: `apps/api/src/media-mailer.ts`.
- **The login card already exists**: `apps/editor-web/src/LoginGate.tsx` (478 lines) +
  `login-gate.css` (636 lines) + `login-title-matrix.tsx` + `login-contact-history.ts`, with a
  Gmail/Telegram/Token method switcher and OTP boxes. Icons already present at
  `apps/editor-web/public/assets/icons-login/{gmail-64.png,telegram-64.png}`.

**Consequence for the plan:** Part 2 is NOT an auth project. Auth is reuse + polish. The real
work is the **landing page design, stripping the editor out of the web build, and deploying**.
Do not plan an OAuth/PKCE/consent-screen workstream. If Google OAuth proper is ever wanted it is
a separate future decision, not this plan.

## 7. Execution model for the resulting plan

- **Orchestrator:** Antigravity (the owner spawns it himself).
- **Implementor workhorse:** Kilo CLI, model `kilo/kilo-auto/efficient`.
- Therefore every task must be written so a *cheap, efficient model* can execute it without
  inventing context: exact file paths, exact acceptance checks, explicit "do not touch" lists,
  and a stated verification command per task.
- Known operational reality: Kilo has previously returned `429 Too Many Requests` and produced no
  diff. Tasks should be small and independently resumable.
