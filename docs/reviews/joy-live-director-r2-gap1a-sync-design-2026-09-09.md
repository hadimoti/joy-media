# GAP 1a — Look Instances server synchronization (Option A) — design

Owner approved Option A (`develop + test the additive migration and API changes`;
**does NOT authorize applying to production now**; final migration/deploy gated by
external Astra candidate-specific approval).

## Requirements (owner, verbatim mapping)

| #   | Requirement                                                                                                            | Design response                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Visual doc + Look Instances share **one atomic CAS update**                                                            | Both written under the **same `revision_id`** in one transaction. New nullable `look_instances jsonb` column on `project_documents` (not a sibling table — keeps the one-row-per-revision CAS). The PUT body carries both; the store writes one row.                                                                                                                                                                                                                                                                                                                                                              |
| R2  | Legacy requests that **omit** Look Instances **preserve** existing records; omission ≠ deletion                        | PUT body: `lookInstances` **optional**. When absent, the store **copies forward** the previous revision's `look_instances` value into the new row. Only an explicit `lookInstances: {..., instances: {}}` (or a populated doc) replaces it.                                                                                                                                                                                                                                                                                                                                                                       |
| R3  | Explicit empty state supports intentional removal                                                                      | `lookInstances: { id, schemaVersion: 1, instances: {} }` present in the body → the new row stores `{}`. Distinguished from absent (R2).                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| R4  | Hydration cannot silently overwrite newer local changes or detach Looks                                                | `hydrateProjectDocument` already guards the visual doc with the local-revision check (`session.projectRevisionId !== localRevision → local-changed`, no write). The Look Instances document rides the **same** hydrate decision: apply the remote `lookInstances` only on `kind: 'hydrated'` (local unchanged), via a new `session.synchronizeLookInstances(doc)`. On `local-changed` the local Look doc is kept untouched, same as the visual doc. A remote doc that is **absent** (older server row) is treated as "no Look info" → the local Look doc is **kept**, never cleared.                              |
| R5  | Validate schema, ownership, payload limits, binding consistency                                                        | `validateProjectDocumentRecord` gains a `lookInstances` branch → `validateLookInstancesDocument`. Ownership: same `owner_id` check as the visual doc (one row). Payload: `look_instances` counted against the existing document-route body size limit; add an explicit per-document instance-count / byte cap. Binding consistency: reject a PUT whose `lookInstances` instance `entityBindings` name a `visualObjects` key **not present in the same PUT's `document`** (the client already enforces this via `#assertLookInstanceReferencesResolve`; the server re-checks — defence in depth, and it is cheap). |
| R6  | Test conflicts, retries, legacy clients, cross-device round trips                                                      | See "Tests".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| R7  | Use the migration number **actually available**; do not assume schema 6                                                | **Inspect `postgres-schema.ts` / the migration ledger first**; `postgres-schema.ts` is idempotent DDL (`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`) rather than a numbered-migration list — the addition is one more `ALTER TABLE project_documents ADD COLUMN IF NOT EXISTS look_instances jsonb`. Confirm whether a separate numbered migration file/counter (the "schema 5" the deploy runbook cites) exists and claim the next free number there.                                                                                                                               |
| R8  | Update backup / migration / compatibility / rollback docs; prefer rollback that **retains** the additive column + data | The column is additive + nullable → forward deploy is safe with old readers (they ignore the column). Rollback: **keep the column** (a `DROP COLUMN` would lose operator Look records that only exist server-side after a cross-device edit). Document: "rollback = deploy the previous API build; the `look_instances` column and its data remain and are simply not read." A destructive `DROP COLUMN` is a separate, explicit, last-resort step, never the default rollback. Update `joy-live-director-r2-deploy-runbook` (currently says "no Postgres migration").                                            |
| R9  | Final migration/deploy gated by Astra candidate-specific approval                                                      | Recorded; the code + migration land on the branch, tested against the in-memory + a local Postgres store, but `POSTGRES_MIGRATIONS` / the production apply is deferred.                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Surface

- `packages/project-schema` — reuse `validateLookInstancesDocument` (done).
- `apps/api/src/postgres-schema.ts` — `ALTER TABLE project_documents ADD COLUMN IF NOT EXISTS look_instances jsonb`.
- `apps/api/src/project-document-store.ts` — `ProjectDocumentRecord.lookInstances?`; `validateProjectDocumentRecord` branch; `InMemoryProjectDocumentStore.writeDocument` carry-forward-on-absent + explicit-empty; `readDocument` returns it.
- `apps/api/src/postgres-control-plane.ts` `PostgresProjectDocumentStore` — read/write the column; carry-forward on absent.
- `apps/api/src/http-server.ts` + `project-document-sync-request-validation.ts` — PUT/GET body/response shape; size cap.
- `apps/editor-web/src/control-plane-client.ts` — `syncProjectDocument` params + `BrowserProjectDocument` gain `lookInstances?`.
- `apps/editor-web/src/project-document-hydration.ts` — apply remote `lookInstances` only on `hydrated`; new `ProjectHydrationSession.synchronizeLookInstances`.
- `apps/editor-web/src/project-document-autosync.ts` — queue `session.lookInstances` alongside `session.visualProject` (the revision already moves on a Look write via `:looks=N`, so `schedule` already fires).
- `apps/editor-web/src/App.tsx` — `bootstrap` applies it; `EditorSession.synchronizeLookInstances` (snapshot-only, no history entry, like `synchronizeVisualProject`).

## Tests

- `project-document-store` (api): write with `lookInstances` → read back; write **without** → previous value carried forward (R2); write explicit `{instances:{}}` → cleared (R3); malformed `lookInstances` → `invalid-document` (R5); binding names an object absent from the same PUT's `document` → rejected (R5); over the instance cap → rejected.
- CAS: two writers, one `baseRevisionId` → second conflicts, neither the visual doc nor the Look doc half-applied (R1, R6).
- `project-document-hydration` (editor): remote `hydrated` with a `lookInstances` → `synchronizeLookInstances` called; `local-changed` → **not** called, local Look doc intact (R4); remote row with `lookInstances` **absent** → local Look doc kept, not cleared (R4).
- Round-trip: apply a Look on session A → autosync → session B bootstraps from the server → the Look Instance is present and reopenable (the scenario the audit flagged).
- Legacy: a GET response with no `lookInstances` key → client treats as absent, keeps local (R6).
