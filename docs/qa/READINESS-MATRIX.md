# JOY Media readiness matrix

Audit date: 2026-10-17. Source baseline: `c1fffd59d5078902e031e7684e69c27df40ce607`.
Lockfile SHA-256: `40f9c7a6cd77056f0faf03543ebac68c7413b8eb99ed82d2bd4b6c3b9ab33968`.
The Windows command baseline is recorded in [the evidence note](evidence/2026-10-17-windows-baseline.md).

This matrix maps the documented CLI commands, the editor's File/Edit/Clip/Agent/View/Window
menus and workspace panels, and the Windows host lifecycle to an executable scenario or an
explicit open gap. `Partial` means existing tests or source behavior cover part of the contract;
it is not acceptance. `Open` means the closeout scenario has not passed. Experimental, hidden,
or deferred features are tracked for honest product status and do not count as ready supported
workflows.

The release validator currently requires the eight P0 rows marked **gate-required**. Other rows
remain tracked gaps; when one becomes a supported release claim, add it to
`REQUIRED_SCENARIOS`, add its deterministic test and evidence path, and update this matrix in the
same change. Evidence for every required row must match the same candidate SHA and pass first try
with zero retries.

## Required acceptance gate

The release evidence must contain passing first-attempt results with zero retries for:

1. `cli.render.playable`
2. `cli.render.unsupported-features`
3. `cli.render.failure-recovery`
4. `cli.render.windows-entrypoints`
5. `project.persistence.fresh-process`
6. `desktop.app.restart-save-export`
7. `desktop.windows.installed-lifecycle`
8. `release.exact-candidate-two-pass`

`release.exact-candidate-two-pass` is evaluated by the existing
`.github/workflows/release-candidate-v2.yml` exact-source two-pass gate. A successful source
build, worker self-test, browser-only export, plan manifest, skipped required scenario, or
unsigned staging package does not satisfy these rows. The owner-confirmed CLI requirement is a
playable file that FFprobe can inspect and a decoder can read; a render-plan manifest alone is
not sufficient.
