# JOY Media v1.1.1 — test matrix

**Card:** T-A01 (test matrix document). **Owner of the matrix:** MC (mcode CLI), worktree `v111-ui`, branch `v111/qa-docs`.
**Written:** 12 Nov 2026. **Status:** the matrix exists; no test in it has been run yet. Running them is T-A05 to T-A15.

This is the single list of what "tested live" means for v1.1.1. Every row has one ID, one owning task, one way to run it and one evidence file. A row is not closed until its evidence file exists and the result is recorded as `passed`.

---

## 1. How to read this

| Column       | Meaning                                                                                                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ID**       | `D-001…` desktop app · `L-001…` command line · `I-001…` installer                                                                                                     |
| **Area**     | The surface under test, as the user sees it                                                                                                                           |
| **Proves**   | The single claim the row proves. If it cannot fail, the row is wrong                                                                                                  |
| **Run**      | `scripted` = a driver script we write · `attended` = the attended harness (owner at the PC) · `manual` = Windows-MCP driven by a helper · `sandbox` = Windows Sandbox |
| **Steps**    | The minimum steps that make the row meaningful                                                                                                                        |
| **Expected** | The observable outcome. `result.json` carries `pass`/`fail`                                                                                                           |
| **Evidence** | File under `C:\jgp\v111\evidence\<owning task>\`                                                                                                                      |
| **Task**     | The card that owns the row and writes the evidence                                                                                                                    |

**Launch rule.** Every desktop row runs under the launch rule of `03-TASK-CARDS.md` section 0: lock file `C:\jgp\LOCK-app-run.txt`, `joy://` key hash checked before and after, a scratch `--user-data-dir` and a scratch library, and the owner library file count equal before and after. A row that needs a sign-in keeps the real `LOCALAPPDATA` (T-J04). No row may write into `C:\Users\HadiMoti\joy-media-assets` or `Documents\JOY Projects`.

**Result file.** Every scripted row writes `result.json` with `{ id, status: "passed" | "failed", detail, durationMs }` next to its evidence. A failed row gets a defect entry in `docs/qa/v1.1.1/DEFECTS.md` (T-A16 format).

**Exit codes (all CLI rows).** `0` ok · `1` failure · `2` usage error · `130` interrupted. The CLI states them in its own help text (`apps/cli/src/cli.ts:295`).

**Sources read to build this matrix.**
`apps/editor-web/src/app-menu.ts` · `AppMenuBar.tsx` · `WorkspaceSwitcher.tsx` · `panel-metadata.ts` · `panel-tab-icons.ts` · `workspace.ts` · `workspace-presets.ts` · `apps/cli/src/cli.ts:117-315` · `packages/commands/src/commands.ts:196-290` · `packages/export-core/src/index.ts` · `tooling/release/src/attended-receipt.ts:13-51` · plan `INDEX.md` (32 screenshots) and `fable-ui-review-2026-11-12.md`.

## 10. Known gaps found while writing this

1. **The View menu does not list the nested panels.** `captions`, `text`, `audio`, `transitions`, `color`, `motion` and `templates` are `nested: true` in `panel-metadata.ts`, so `panelsForIntent` leaves them out of `view.panel.*`. They have no menu path at all today — only the panel hub. The rows D-019 to D-032 therefore cover 14 panels; the other 7 are covered in section 3.4 through their own tabs, not through the menu. **CC should decide whether the View menu should carry them.**
2. **The Clip menu has one item.** `clip.split` is the whole Clip menu (the review's P2-13 asks for Split, Duplicate, Delete, Speed, Detach audio). The other four actions exist elsewhere (Edit menu, Inspector). **CC should decide whether they move into the Clip menu**, because then the menu id set changes and this matrix must be regenerated.
3. **`window.panel.*` only covers four panels** — Create, Program Monitor, Timeline and Inspector (`WINDOW_PANELS` in `app-menu.ts:49-54`). The other panels have no "Focus" entry.
4. **The palette and the menus disagree on wording.** The review found `Mod+Z` in the palette and `Ctrl+Z` in the menus. Row D-071 checks that they now agree.
5. **Exit code 130 is only reachable in `agent chat`.** It is a terminal-only path, so the row L-007 needs a pty; the driver must use one.

6. **The two export preset lists do not match.** The app has five (`social-h264-aac`, `reels-1080`, `shorts-1080`, `youtube-1080`, `high-bitrate`, in `packages/export-core/src/index.ts`) and the command line has three (`mp4`, `webm`, `prores`, in `joy-media render --preset`). They are different axes: size and bitrate on one side, container and codec on the other. Section 5 and rows L-035 to L-037 therefore test two separate lists, and **CC should decide which one is the product's preset list** before T-A10 runs, because a mismatch here means the app and the command line can produce different files for the same request.
