## EOF loop, Space transport, and timeline-follow acceptance (2026-08-11)

Commit `1fce9c1` adds a native EOF transition back to the first playable frame,
keeps playback active across the wrap, and uses a playback epoch/intent guard so
an older asynchronous media load cannot restart playback after Space pauses it.
Held Space is ignored, text and interactive controls retain their own Space
behavior, and a failed boundary sync now stops honestly. The editor regression
suite passed before deployment.

A signed-in Chrome run played the owner-library source through its real
115.966633-second EOF. It wrapped to the start with the media still unpaused and
both transport surfaces still showing Pause. Space then held media time exactly
constant while paused and resumed from that position on the next Space press.

Commit `8567f3e` makes timeline duration the maximum of the composition shell,
authored clip ends, and marker times. Fit therefore uses the full 116-second
source instead of the old 60-second shell and can select sub-5 px/s scales for
arbitrarily long content. At the live 2439x1122 Chrome viewport, Fit produced
`clientWidth=1846`, `scrollWidth=1846`, and a 1653px clip lane ending inside the
visible timeline. After Zoom In, the timeline expanded to 2260px; playback on
the final page moved `scrollLeft` to 413.33px while the playhead remained inside
the 1846px viewport and both 168px gutters stayed sticky. The EOF loop reset
`scrollLeft` to 0 without stopping. A final Space check held source time with
zero delta for 2.5 seconds, then resumed it. The temporary timeline placement
was removed; the uploaded original remains in the owner Video library.
