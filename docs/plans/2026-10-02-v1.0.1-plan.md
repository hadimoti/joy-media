### Reviewed and found sound (no action)

- **OTP delivery diagnostics** (`0cafd13`): `sanitizeOtpDeliveryError` whitelists SMTP error code, 4xx/5xx response code and command token only; the OTP value and recipient never reach the log. Diagnostics callback is wrapped so it can never mask the original failure.
- **Alchemy webhook** (`6bb6d67`): HMAC-SHA256 over the raw request bytes with `timingSafeEqual`; checkout is behind `JOY_MEDIA_USDC_CHECKOUT_ENABLED` and reports `CHECKOUT_DISABLED` otherwise.
- **Secrets scan**: no `.env` ever committed in the window; the only key-shaped strings added are obvious test fakes; the only IPv4 literals outside tests are RFC 5737 documentation ranges and a `169.254.169.254` SSRF guard test.
- **"100% green" commit** (`2408f82`) added 110 `expect` calls and removed 18, with no config changes to vitest or playwright — it did not get green by weakening tests.
- **Large media**: three ~1 MB reference MP4s under `apps/editor-web/public/media/reference/`; acceptable, but do not grow this directory.

## 3. v1.0.1 release checklist

1. **Merge the review-fixes PR** (this branch): installer guard + version constant, format fixes, cruft removal, `.mailmap`, audit-doc note, this plan.
2. **Enable CI on push/PR** (P1): in `.github/workflows/ci.yml` add
   ```yaml
   on:
     workflow_dispatch:
     pull_request:
     push:
       branches: [main]
   ```
   and turn on branch protection for `main` requiring the `ci` workflow. Update `tooling/release/src/ci-runner-policy.test.ts` if it asserts on triggers.
3. **Delete the retired Creative Brief tests** (C3) in its own PR.
4. **Bump version**: `InstallerEngine.ProductVersion = "1.0.1"` in `Setup.cs`; `"version": "1.0.1"` in `apps/desktop/package.json` and `apps/cli/package.json`.
5. **Build**: `pnpm --filter @joy-media/desktop package` → `apps/desktop/installer/build-installer.ps1 -Version 1.0.1`.
6. **Verify the exact SHA**: dispatch `release-candidate-v2` with the candidate `main` SHA; require `gate-summary` green on both passes. Record the run URL.
7. **Release notes** `RELEASE_NOTES_v1.0.1.md`: copy the v1.0.0 SmartScreen notice; list C1/C2/C4 and the CI change; fresh SHA256 for both artifacts; link the CI run.
8. **Tag and publish** `v1.0.1` on that SHA only after step 6 is green. Run `pnpm format:check` on the release-notes commit before tagging (this is what broke `pnpm check` at v1.0.0).
9. **Post-release**: add a one-paragraph note to `docs/archive/` about the Sep 15 history import (P6).
