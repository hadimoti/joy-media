## Step 2 — Build the desktop payload and compile the installer

Note: `package:installer` invokes `package-release.mjs --unpacked` internally to generate an intermediate staging bundle, then separately assembles the unsigned distributable archive and installer. Building these artifacts does not clear the separate owner/legal publication gate.

```powershell
pnpm --filter @joy-media/desktop build
pnpm --filter @joy-media/desktop package:installer
# expected: apps\desktop\dist\releases\joy-media-windows-x64-v1.0.1.zip
powershell -NoProfile -ExecutionPolicy Bypass -File apps\desktop\installer\build-installer.ps1 -Version 1.0.1
# expected: apps\desktop\dist\releases\joy-media-setup.exe
```

`build-installer.ps1` compiles `Setup.cs` with the .NET Framework `csc.exe` and refuses to run if `-Version` does not match `ProductVersion` in `Setup.cs`. If it throws for any other reason, that is a C# compile error in the new guard code: fix it minimally in `Setup.cs`, re-run, and include the diff in your report. Then smoke the packaged app:

```powershell
pnpm --filter @joy-media/desktop test:smoke-packaged
pnpm --filter @joy-media/desktop test:smoke-standalone
node tests\desktop\installer-package-check.mjs
```

Install `joy-media-setup.exe` once on this PC (accept the SmartScreen "Run anyway"), confirm the app launches, that Add/Remove Programs shows `JOY Media 1.0.1`, that `joy.cmd --version` on a fresh terminal prints `1.0.1`, then run `uninstall.cmd` from the install directory. Record the results.

Compute the hashes:
